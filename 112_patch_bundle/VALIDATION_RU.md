# Фактическая проверка комплекта

Проверено 24.09.2026 в изолированной копии исходников из `112 (10).txt`.

Среда проверки: Python **3.12.14**, Node.js **24.19.0**, Git **2.51.1**. Это фактически доступные версии инструментов проверки, а не требование обновить ими сервер/голос коллеги.

| Проверка | Результат |
|---|---|
| 24 Python-теста адресов, условий зачёта, прогноза, BKT, SQLite, аналитики и ML | Пройдены |
| Вложенная транзакция и откат при внедрённой ошибке сохранения квитанции | Пройдены: результаты, BKT и события не сохранились; LIVE восстановлен |
| Повторное завершение через обёртку команды | Пройдено: сохранённый ответ, без повторного начисления |
| DDS-оценщик без FastAPI: только приём, неподтверждённые статусы, сохранённый порог | Пройдено на извлечённой реальной функции; это не HTTP-тест |
| Синтетическое обучение ML, независимость признаков от эталона, разделение пользователей/времени | Пройдено; качество на реальных обучающихся этим не доказано |
| Синтаксис Python и трёх JS-файлов | Пройден |
| 5 frontend smoke-сценариев с упрощённым DOM | Пройдены: неизвестная речь, скрытая группа в списке ДДС, результат ДДС, холодный старт аналитики, экранирование событий |
| Хеши Python-функций ASR/TTS/health, caller.py, JS-обработчиков записи/воспроизведения | Совпадают с исходной версией |
| Применение `all.patch` к чистой исходной копии | Пройдено, 28 изменённых/новых файлов совпадают с manifest |
| Применение четырёх отдельных патчей по очереди | Пройдено, результат совпадает с `all.patch` |
| Обратное применение исходников | Пройдено, первоначальные хеши восстановлены |
| Повторное применение полного комплекта | Отклонено до изменения файлов; хеши не изменились |
| Повторный запуск 24 Python + 5 frontend-проверок в копии, полученной именно применением патча | Пройден |
| 8 настоящих API-тестов FastAPI TestClient | **Не выполнены**: в среде отсутствуют FastAPI, HTTPX, python-multipart; установка зависимостей заблокирована сетевой политикой среды |
| PostgreSQL smoke | **Не выполнен**: тестовая PostgreSQL-БД не предоставлена |
| Настоящий браузер, ASR/TTS, живой LLM, нагрузка, визуальная вёрстка PDF | **Не выполнены**: нужны рабочий стенд и ручная приёмка |
| Обучение/калибровка на реальных данных заказчика | **Не выполнены**: данных нет; ML по умолчанию выключен |

Логи: `verification.log`, `application_check.log`, `integration_unavailable.log`, `postgres_unavailable.log`.

Интеграционный запуск намеренно заканчивается `NOT ACCEPTED` и ненулевым кодом, когда требуемый прогон недоступен. Это не ошибка, скрытая за зелёным `unittest`: недостающий уровень проверки явно обозначен.

Для выкладки ещё нужны: API-прогон в окружении проекта, PostgreSQL-проверка, ручные сценарии из `TESTING_RU.md`, слияние с реальной веткой коллеги и проверка задержек при одном worker. До этого комплект следует считать кандидатом для стенда.
