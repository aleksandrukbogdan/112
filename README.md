# Тренажёр и помощник оператора 112

Два режима на одном движке: **обучение** и **поддержка**.
Вся нормативка вынесена в `config/` — меняется правкой YAML, без правки кода.

---

## 1. Что это

| Режим | Заявитель | Подсказки | Оценка | URL |
|---|---|---|---|---|
| **Обучение** | генерирует LLM | видны | сразу после вызова | `/trainee` |
| **Поддержка** | живой человек | видны | только в разборе | `/assistant` |

Различие ровно в двух вещах: источник реплик и право показывать оценки в эфире.
Движок протокола, УКИО, классификаторы, нормативы — общие.

### Принцип адаптируемости

> **В коде — механика. В `config/` — всё, что установлено нормативным актом.**

Ни одного классификатора, порога, вопроса или названия службы в `.py` и `.jsx`.

**Проверка принципа:** переход на другой субъект РФ = скопировать
`config/regions/so.yaml` и поправить значения. Если пришлось лезть в код —
это баг, а не задача.

### Вводные Москвы и аудит

ТЗ Деп. обороны и ЧС и памятка АРМ-112 (ГБУ «Система 112») разобраны отдельно:
каталог, реестр требований и сверка с этим кодом — в [`docs/vvodnye/`](docs/vvodnye/katalog.md).

## 3. Архитектура

```
                        config/  ← ВСЁ НОРМАТИВНОЕ
                           │
                  config_loader.py
                           │
                  ProtocolEngine  ← общий движок опроса
                     ╱          ╲
            режим train      режим assist
         заявитель = LLM    заявитель = ASR
                     ╲          ╱
                  rech_check + hints
                           │
              оценка · журнал · отчёты 1/112, 2/112
```

### Как работает движок

```
реплика оператора  ──►  какие вопросы уже прозвучали
реплика заявителя  ──►  флаги обстановки (частный дом, трасса, паника)
заполнение поля    ──►  автоматика (уровень ЧС, состав служб)
                            ▼
                   подсказки по весу:
                   1. правила по обстановке (психолог, переводчик)
                   2. условные вопросы (километр трассы, газификация)
                   3. таймер норматива
                   4. незаданные обязательные вопросы
```

Условные ветки — из приложения № 11: перекрёсток требует вторую улицу,
частный дом — газификацию, ДТП на трассе — километр и направление,
объект с массовым пребыванием — число людей и меры эвакуации.

Отслеживание заданных вопросов опирается на идею из работы Corti
«MultiQT: Multimodal Learning for Real-Time Question Tracking in Speech»
(arXiv:2005.00812). Сейчас лексическая версия; место под ML-классификатор —
в методе `ProtocolEngine._pohozh`.

## 6. Развёртывание

**Подробная пошаговая инструкция — в `RAZVERTYVANIE.md`.**
Ниже краткая версия.


### Что разворачивается само, а что нет

| Компонент | Compose | Модель |
|---|---|---|
| Postgres 16, Redis 7, API, Web | **да** | — |
| **ASR** | **да**, профиль `speech` | GigaAM `v3_e2e_rnnt` + эмоции, GPU |
| **TTS** | **да**, профиль `speech` | Silero `v4_ru`, голос `xenia` |
| **LLM** | **НЕТ, отдельно на хосте** | Qwen3-VL через vLLM, порт 1212 |

Веса ASR и TTS скачиваются автоматически в `./models`. Первый запуск
до 10 минут — у ASR в healthcheck `start_period: 300s`, это не зависание.

### LLM запускается отдельно

```bash
python -m vllm.entrypoints.openai.api_server \
  --model /path/to/Qwen3-VL \
  --served-model-name Qwen3-VL \
  --port 1212 \
  --gpu-memory-utilization 0.85 \
  --max-model-len 8192 \
  --enable-prefix-caching
```

`--enable-prefix-caching` обязателен: `llm.py` ставит статичную часть
промпта первой, чтобы KV-кэш переиспользовался между ходами диалога.

**`--served-model-name` должно совпадать с `LLM_MODEL` в `.env`.**
Самая частая причина, когда всё поднялось, а заявитель молчит.

```bash
curl -s http://localhost:1212/v1/models | python3 -m json.tool
```

### GPU

В `.env`: нулевая карта под LLM, первая под речь (`SPEECH_GPU=1`).
На одной карте они дают плавающие таймауты вместо честной ошибки.
Несколько карт: `SPEECH_GPU=1,2`.

### Запуск

```bash
cd /data/112
make config-check     # проверить config/ ДО запуска
make ports
make up               # текстовый режим, ~1 минута
make up-speech        # с ASR и TTS, первый раз до 10 минут
make prewarm
make seed
make health
```

### Проверка

```bash
curl -s localhost:21121/health
curl -s localhost:21121/api/v2/config | python3 -m json.tool | head -30
curl -s localhost:21124/health   # ASR
curl -s localhost:21125/health   # TTS
```

## 7. Доступ с других компьютеров

Выбор режима определяется одним вопросом: **нужен ли микрофон.**

Браузер даёт доступ к микрофону только в защищённом контексте —
`https` либо `localhost`. По `http://адрес:21120` записи не будет.
SSH-туннель решает это тем, что для браузера адрес становится `localhost`.

### Туннель — для тренировок

На сервере:
```bash
make close
make tunnel
```

На своём компьютере, `~/.ssh/config`:
```
Host nir
    HostName 10.109.50.250
    User ваш_логин
    IdentityFile ~/.ssh/nir_gpu1_ed25519
    IdentitiesOnly yes
    LocalForward 21120 localhost:21120
    LocalForward 21121 localhost:21121
    ServerAliveInterval 30
```

```bash
chmod 600 ~/.ssh/nir_gpu1_ed25519
ssh -N nir            # затем http://localhost:21120
```

Пробрасывать нужно **оба порта**: 21120 — интерфейс, 21121 — API,
куда браузер ходит напрямую. Один порт — страница откроется пустой.

`IdentitiesOnly yes` нужен при нескольких ключах, иначе сервер отвергнет
подключение, исчерпав лимит попыток.

### Открытые порты — для показа

```bash
make open      # определит адрес, перепишет .env, пересоздаст контейнеры
make status
make close
```

`make open` **пересоздаёт** контейнер web, а не перезапускает:
`NEXT_PUBLIC_API_URL` вкомпилируется в клиентский бандл при старте Next,
обычный `restart` её не подхватит.

## 10. Что менять, когда придут документы

Из 22 классификаторов **пять помечены заглушками**. Интерфейс показывает
их количество в шапке, чтобы на демонстрации не выдать заглушку
за утверждённый норматив.

| Файл | Чем заменить | Приоритет |
|---|---|---|
| `classifiers/tip_proisshestviya.yaml` | «Алгоритм опроса по видам происшествий» от ГКУ СО ТЦМ | **высокий** |
| `classifiers/ulica.yaml` | справочник ФИАС | средний |
| `classifiers/mesto.yaml` | полный ОКАТО региона | средний |
| `classifiers/obekt.yaml` | справочник объектов ОКПО | низкий |
| `classifiers/doroga.yaml` | реестр дорог региона | низкий |

### Порядок замены

```bash
vim config/classifiers/tip_proisshestviya.yaml   # заменить items
# убрать строку status: ZAGLUSHKA, указать istochnik
make config-check
make config-reload        # применяется БЕЗ перезапуска контейнеров
```

**Код не трогается.**

### Добавить регион

```bash
cp config/regions/_template.yaml config/regions/chel.yaml
vim config/regions/chel.yaml
echo "REGION=chel" >> .env
make config-reload
```

### Добавить протокол по виду происшествия

Создать `config/protocols/pozhar.yaml` по образцу `_base.yaml`
и указать имя в поле `protokol` соответствующего типа происшествия.

## 11. Что заморожено до реальных данных

Не отменено — отложено, потому что без корпуса размеченных вызовов
проверить нечем.

- ML-классификатор заданных вопросов (сейчас лексический)
- Приоритизация очереди вызовов
- Подсветка признаков угрозы жизни в речи
- Автоматическое закрытие непрофильных вызовов — **и не будет**:
  закрывать вызов без человека нельзя

Отдельно: **инструкции до прибытия** (СЛР по телефону) в помощнике
отсутствуют намеренно. Это медицинское вмешательство под руководством
немедика. В MPDS оно работает, потому что протоколы утверждает медицинский
директор службы, а оператор сертифицирован IAED; российского аналога такого
механизма нет. В тренажёре — можно, там нет пациента.

## 12. Журнал подсказок

Каждая показанная подсказка и реакция оператора пишутся в `hint_log`.

Это не формальность. В мае 2026 пожарное управление Сиэтла, применявшее
ИИ-подсказки диспетчерам с декабря 2023, не смогло объяснить журналистам,
как измеряет успешность технологии. Если через два года спросят, как
система влияла на решения, — ответ должен быть в базе, а не в памяти.

Позиция «окончательное решение всегда за оператором» — единственная
защитимая конструкция.

## 13. Известные ограничения

Осталось одно, и оно требует данных, а не кода:

- **Распознавание заданных вопросов лексическое.** Ошибается на
  перефразировках: «где вы находитесь» и «назовите адрес» — один вопрос,
  но совпадут по-разному. Правильное решение — мультимодальный
  классификатор по образцу Corti MultiQT (аудио + расшифровка), но его
  не на чем обучить, пока нет корпуса размеченных вызовов. Интерфейс
  под замену готов: метод `ProtocolEngine._pohozh`, менять только тело.

Закрыто в этой версии:

- ~~сессии в памяти процесса~~ → Redis, переживают перезапуск, TTL 6 ч
- ~~`next@14.2.15` с критической уязвимостью~~ → `^14.2.35`, lock перегенерирован
- ~~списки в спец.частях не рендерятся~~ → подозреваемые, больные и ТС
  добавляются и удаляются в интерфейсе
