# Тренажёр оператора 112 / диспетчера ДДС · Москва

Учебная система для операторов «Системы 112» и диспетчеров дежурно-диспетчерских служб (ДДС).
Обучающийся принимает вызов от виртуального заявителя (текстом или голосом), заполняет карточку
происшествия, классифицирует его и назначает службы; в режиме ДДС — проверяет карточку по записи
разговора, связывается с бригадой по IP-телефону и проставляет статусы. Оценка выставляется
правилами (граф доказательств со ссылками на нормативы), а не нейросетью.

Заказчик — Департамент ГОЧСиПБ города Москвы.

## Быстрый локальный запуск

Все три способа поднимают одно и то же приложение. Для проверки функциональности достаточно первого
или второго: без языковой модели заявитель отвечает по правилам, без речевых сервисов работает
текстовый режим, оценка от них не зависит.

### Способ 1. Без Docker (Python + SQLite), 2 минуты

Нужен Python 3.12.

```bash
git clone <URL_РЕПОЗИТОРИЯ> t112 && cd t112
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements-release.txt

mkdir -p state/app
export DATA_DIR=$PWD/data \
       DB_PATH=$PWD/state/app/t112.db \
       BACKUP_DIR=$PWD/state/app/backup \
       LLM_ENABLED=false \
       VOICE_URL=http://127.0.0.1:8090 \
       ASR_URL=http://127.0.0.1:8091
uvicorn api.main:app --host 127.0.0.1 --port 8080 --workers 1
```

Windows (PowerShell):

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements-release.txt
mkdir state\app -Force
$env:DATA_DIR="$PWD\data"; $env:DB_PATH="$PWD\state\app\t112.db"; $env:BACKUP_DIR="$PWD\state\app\backup"
$env:LLM_ENABLED="false"; $env:VOICE_URL="http://127.0.0.1:8090"; $env:ASR_URL="http://127.0.0.1:8091"
uvicorn api.main:app --host 127.0.0.1 --port 8080 --workers 1
```

Откройте http://localhost:8080.

Если у вас запущена локальная модель с OpenAI-совместимым API, вместо `LLM_ENABLED=false` укажите
`LLM_BASE_URL=http://localhost:1212/v1` и `LLM_MODEL=<имя модели>`.

### Способ 2. Docker, минимальный состав (БД + приложение)

Нужны Docker 24+ и Docker Compose 2.20+.

```bash
git clone <URL_РЕПОЗИТОРИЯ> t112 && cd t112
cp .env.example .env              # при желании смените DB_PASSWORD
mkdir -p state/pg state/app
docker compose up -d --build db app
```

Откройте http://localhost:8080. Проверка состояния: `curl http://localhost:8080/health`.

### Способ 3. Полный стек с голосом и GPU

```bash
make up        # БД, приложение, голос, GigaAM и F5-TTS на GPU
make up-cpu    # без видеокарты: распознаёт Vosk, синтезирует Piper
make up-llm    # дополнительно поднять модель в контейнере vLLM
make health    # сводка по всем компонентам
```

Требования, выбор видеокарт, подключение модели и доступ с другого компьютера описаны в
[docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Учётные записи первого запуска

При пустой базе создаются учебная группа и пользователи. Пароли можно задать заранее переменными
`ADMIN_PASSWORD`, `TEACHER_PASSWORD`, `TRAINEE_PASSWORD`; если они пусты, используются стандартные:

| Логин | Пароль | Роль |
|---|---|---|
| `admin` | `admin112` | администратор |
| `teacher` | `teacher112` | преподаватель |
| `trainee`, `trainee2` | `trainee112` | обучающийся |

Стандартные пароли подходят только для демонстрации — смените их через кнопку «Пароль».

## Что посмотреть за 5 минут

1. Войдите как `trainee` → «Приём вызова 112» → «Билет 1, вызов 1».
2. Спросите заявителя «Где это?» — он назовёт ориентир; точный адрес он сообщит только после
   уточняющего вопроса.
3. Заполните карточку, выберите тип происшествия по классификатору, службы подставятся — «Отправить».
4. Откройте разбор: каждый критерий показан со ссылкой на норматив и событием, на котором основан.
5. Режим «Диспетчер ДДС»: подтвердите приём за 30 с, сверьте карточку с записью разговора,
   позвоните бригаде, проставьте статусы по мере докладов.
6. Войдите как `teacher`: мониторинг занятий, назначения, генерация сценариев, аналитика группы,
   отчёты по формам 1/112 и 2/112.

## Тесты

Зависимости те же, что для запуска (`requirements-release.txt`).

```bash
python3 scripts/verify_patch.py               # модульные тесты tests/, синтаксис и smoke-тесты JS (нужен Node.js)
python3 scripts/verify_patch.py --integration # + API-тесты FastAPI
python3 scripts/verify_patch.py --skip-js     # без Node.js
```

Тесты используют временную базу и не трогают рабочие данные. Проверка на PostgreSQL описана в
[docs/DEPLOYMENT.md](docs/DEPLOYMENT.md#тестирование).

## Структура репозитория

```
api/            серверная часть (FastAPI): маршруты, оценка, режим ДДС, аналитика, отчёты
web/            интерфейс (статические JS/CSS, без сборки)
data/           классификатор, билеты, службы — источники истины, генерируются build_bilety.py
asr/            контейнер распознавания GigaAM (GPU)
voice/          контейнер Vosk + Piper (CPU)
tts/            контейнер синтеза F5-TTS (GPU)
deploy/         установщик обновлений, диагностика, TLS, офлайн-поставка
scripts/        тесты, экспорт и обучение ML-прогноза
tests/          модульные и интеграционные тесты
docs/           документация
docker-compose.yml, Dockerfile, Makefile, .env.example
```

Каталог `state/` (база, ключ подписи сессий, резервные копии) создаётся при запуске и в репозиторий
не входит.
