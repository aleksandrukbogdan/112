# Инструкция: установка, запуск, работа

Тренажёр оператора ДДС · Департамент ГОЧСиПБ города Москвы

Выполняйте разделы по порядку. Всё поднимается с нуля одной командой; интернет нужен только при первой сборке.

---

## 1. Что разворачивается

```
  ВАШ ПК                               СЕРВЕР
  браузер ──SSH-туннель──► t112        приложение: интерфейс + API          CPU
  localhost:8080            │
                            ├──► t112-db     PostgreSQL 16 — вся база       CPU
                            ├──► t112-asr    GigaAM v3 — распознавание      GPU
                            ├──► t112-voice  Vosk (запасное распознавание)
                            │                Piper (голос собеседников)     CPU
                            └──► модель      Qwen3-VL через vLLM            GPU
                                 на хосте (как раньше) или контейнер t112-llm
```

| Контейнер | Что делает | Где | Поднимается |
|---|---|---|---|
| **t112-db** | PostgreSQL 16: пользователи, занятия, оценки, сценарии, журнал | CPU | всегда |
| **t112** | интерфейс, API, оценка, аналитика, отчёты | CPU | всегда |
| **t112-voice** | Vosk — распознавание (запасное), Piper — синтез голоса | CPU | всегда |
| **t112-asr** | GigaAM v3 — основное распознавание речи | **GPU** | `make up`, `make up-llm` |
| **t112-llm** | модель Qwen3-VL (vLLM) | **GPU** | только `make up-llm` |

Модель чаще всего уже работает у вас на хосте (порт 1212) — тогда `t112-llm` не нужен, приложение подключится к ней.

**Оценка от модели не зависит**: все факты графа доказательств считаются правилами. Без модели собеседники отвечают по правилам, тренажёр полностью работает.

### Два режима обучения

| Режим | Кто обучаемый | Что делает |
|---|---|---|
| **Диспетчер ДДС** — основной | диспетчер службы | получает карточку от «оператора 112», проверяет её по записи разговора, подтверждает приём за 30 с, звонит бригаде по IP-телефону, ставит статусы по факту докладов |
| **Приём вызова 112** | оператор 112 | принимает вызов, дожимает адрес, классифицирует, назначает службы |

Режим ДДС построен по ответам заказчика: карточку «поставляет» система; у ДДС есть доступ к записи разговора; бригады выбираются вручную; связь — IP-телефон; статусы ставит только диспетчер; старший бригады сам докладывает об этапах или диспетчер звонит ему узнать обстановку.

## 2. Требования

| | Требование | Проверка |
|---|---|---|
| ОС | Linux x86_64 (Ubuntu 22.04/24.04) | `uname -m` |
| Docker / Compose | 24.0+ / 2.20+ | `docker --version`, `docker compose version` |

| Память | 8 ГБ | `free -h` |
| Интернет | только при первой сборке | — |

Нет видеокарты — `make up-cpu`: всё, кроме GigaAM (распознаёт Vosk).

## 3. Куда положить

С вашего ПК:

```bash
scp -i ПУТЬ_К_КЛЮЧУ t112-msk.tar.gz root@10.109.50.250:/tmp/
```

На сервере:

```bash
sudo mkdir -p /data/t112 && sudo chown $USER:$USER /data/t112
tar xzf /tmp/t112-msk.tar.gz -C /data/t112 --strip-components=1
cd /data/t112 && ls
```

`--strip-components=1` обязателен, иначе файлы окажутся в `/data/t112/t112/`.

## 5. Настройка `.env`

`make up` создаст `.env` из образца. Поменять **до первого запуска**:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `DB_PASSWORD` | t112pass | пароль PostgreSQL — **смените** |
| `LLM_BASE_URL` | http://host.docker.internal:1212/v1 | модель на хосте |
| `LLM_MODEL` | Qwen3-VL | **= `--served-model-name`** у vLLM |
| `LLM_ENABLED` | true | false — без модели |
| `ASR_GPU` | 1 | карта для GigaAM |
| `LLM_GPU` | 0 | карта для модели (при `up-llm`) |
| `DDS_ETAPY_SEC` | 45,25,50 | ДДС: через сколько секунд после выезда бригада прибывает, начинает и завершает работы |
| `DDS_VEROYATNOST_OSHIBKI` | 0.7 | ДДС: доля карточек с ошибкой оператора 112 |
| `UCHEBNY_TAYMING_SEC` | 30 | учебный тайминг ТЗ |
| `ADMIN_PASSWORD` и др. | пусто | пароли первого запуска |

Остальные правила — статусы, их основания, какие ошибки вносит «оператор 112» — в `api/config.py`, раздел `DDS`. Правятся без изменения логики.

## 6. Модель (LLM)

### Вариант А — модель уже на хосте (как раньше)

```bash
curl -s http://localhost:1212/v1/models | python3 -m json.tool
```

`id` из ответа впишите в `LLM_MODEL`. Если vLLM слушает только 127.0.0.1 — запустите его с `--host 0.0.0.0`, иначе контейнер его не увидит.

### Вариант Б — модель в контейнере

```bash
make up-llm
```

Поднимется `t112-llm` (образ `vllm/vllm-openai`), скачает `LLM_HF_MODEL` с Hugging Face в `state/hf/` и отдаст её под именем `LLM_MODEL`. Первая загрузка — десятки гигабайт и до 40 минут. Для закрытых моделей укажите `HF_TOKEN`.

Честно: связку «образ vLLM + Qwen3-VL» я не мог проверить у себя. Если контейнер модели не стартует, `docker logs t112-llm` покажет причину; чаще всего это версия образа — задайте конкретную в `VLLM_IMAGE`. Надёжнее вариант А.

## 8. Видеокарты

### 8.1. Проверить, что Docker видит видеокарты

```bash
make gpu-check
```

Ожидаемо:

```
  GPU 0, NVIDIA …, 38000 MiB, 81920 MiB      ← здесь vLLM
  GPU 1, NVIDIA …, 500 MiB, 81920 MiB        ← свободна — сюда GigaAM
  Docker видит GPU: да
  GigaAM будет на карте ASR_GPU=1 (vLLM держите на другой)
```

Если `Docker НЕ видит GPU` — не установлен NVIDIA Container Toolkit (vLLM при этом может работать, если запущен не в Docker). Установка на Ubuntu:

```bash
curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey \
  | sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg
curl -s -L https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list \
  | sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g' \
  | sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list
sudo apt-get update && sudo apt-get install -y nvidia-container-toolkit
sudo nvidia-ctk runtime configure --runtime=docker
sudo systemctl restart docker
make gpu-check
```

### 8.2. Выбрать видеокарту

Посмотрите, на какой карте vLLM: `nvidia-smi` — у неё будет занята большая часть памяти. Впишите **другую** в `.env`:

```
ASR_GPU=1
```

Свободной карты нет — GigaAM всё равно можно поставить на карту с vLLM, если на ней остаётся от 4 ГБ, но тогда уменьшите у vLLM `--gpu-memory-utilization` (например, до 0.80). Либо используйте `make up-voice` — распознавание на CPU через Vosk.


### Какую карту кому

Посмотрите `nvidia-smi`. Модель и GigaAM — **на разные карты**: `LLM_GPU=0`, `ASR_GPU=1`. Одна карта — возможно, если после модели остаётся 4 ГБ; уменьшите тогда у модели `LLM_GPU_UTIL` до 0.80.

Если GigaAM не загрузился (`CUDA out of memory` и т. п.), распознавание автоматически переходит на Vosk — `make health` покажет причину в строке «Примечание».

## 9. Вход со своего компьютера

Сервер слушает только `127.0.0.1` — снаружи его не видно. Это сделано специально. Вход — через SSH-туннель по вашему ключу.

### Разово

На **своём** компьютере (не на сервере):

```bash
ssh -i ~/.ssh/ваш_ключ -N -L 8080:localhost:8080 root@10.109.50.250
```

Окно терминала **оставьте открытым** — пока оно открыто, туннель работает. Команда ничего не пишет, это нормально.

В браузере: **http://localhost:8080**

### Постоянно — через `~/.ssh/config`

Создайте или дополните файл `~/.ssh/config` на своём компьютере:

```
Host t112
    HostName 10.109.50.250
    User root
    IdentityFile ~/.ssh/ваш_ключ
    IdentitiesOnly yes
    LocalForward 8080 localhost:8080
    ServerAliveInterval 30
    ServerAliveCountMax 3
```

После этого достаточно:

```bash
ssh -N t112
```

`IdentitiesOnly yes` нужен, если у вас несколько ключей: без него сервер может отказать, исчерпав лимит попыток. `ServerAliveInterval` не даёт туннелю оборваться при простое.

### Права на ключ (Linux, macOS)

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/ваш_ключ
```

Иначе ssh откажется использовать ключ с ошибкой `UNPROTECTED PRIVATE KEY FILE`.

### Windows

PowerShell в Windows 10/11 понимает те же команды:

```powershell
ssh -i C:\Users\Имя\.ssh\ваш_ключ -N -L 8080:localhost:8080 root@10.109.50.250
```

Конфиг лежит в `C:\Users\Имя\.ssh\config`, формат тот же.

Права на ключ: правой кнопкой по файлу → Свойства → Безопасность → Дополнительно → Отключить наследование → оставить только свою учётную запись.

**PuTTY:** Connection → SSH → Auth → Credentials → указать `.ppk`-ключ; Connection → SSH → Tunnels → Source port `8080`, Destination `localhost:8080` → Add; затем Session → Open.

### Порт 8080 занят на вашем компьютере

Замените левую часть:

```bash
ssh -i ~/.ssh/ваш_ключ -N -L 9090:localhost:8080 root@10.109.50.250
```

и открывайте `http://localhost:9090`.

### Показать коллегам в сети (без микрофона)

```bash
make open     # напечатает адрес вида http://10.109.50.250:8080
make close    # вернуть обратно
```

Порт станет виден всей сети. Для показа годится, для постоянной работы используйте туннель.

## 11. Проверка

```bash
make test        # 63 проверки без docker + маршрутизация речи
make health
```

### Вручную — диспетчер ДДС, 5 минут

1. Вход `trainee` → «Диспетчер ДДС» → откройте любой вызов из списка.
2. Сверху бежит таймер **«до подтверждения 30 с»**. Поставьте статус «Принята» с комментарием — таймер позеленеет.
3. Прочитайте **«Запись разговора 112»** справа и сравните с карточкой: адрес, телефон, пострадавшие. Нашли расхождение — «Проверка карточки» → поле → верное значение → «Отметить расхождение».
4. **IP-телефон** → «Бригада № 1» → «Позвонить». Передайте адрес, что случилось, пострадавших, телефон заявителя. Без адреса бригада не выедет. Ответ «Принял, выезжаем» — положите трубку, поставьте «Начало реагирования».
5. Через ~45 с **зазвонит** старший бригады: «Прибыли на место». Ответьте, поставьте «Прибытие». Дальше — «Проведение работ», «Работы завершены» с комментарием.
6. «Закрыть карточку» → граф доказательств: подтверждение, найдена ли ошибка, полнота передачи, статусы по факту, своевременность, комментарии, речь.

Проверьте и обратное: поставьте «Работы завершены» сразу — система предупредит, что основания не было, и в оценке это не будет засчитано.

### Вручную — приём вызова 112

«Приём вызова 112» → «Билет 1, вызов 1» → «Где это?» (ориентир) → «Уточните номер строения» (эталон) → «Что случилось?»: быстрые кнопки как в АРМ → теги → службы подтянутся → «Отправить карточку».

## 12. Роли

**Обучающийся:** задания (с режимом и службой), «Диспетчер ДДС», «Приём вызова 112», прогресс (BKT, рекомендации, точность прогнозов, сертификат), справка.

**Преподаватель:** мониторинг идущих занятий обоих режимов в реальном времени; генерация и утверждение сценариев; назначения — режим, служба обучаемого, лимит, срок; аналитика группы с тепловой картой и проваливанием до вызова; изменение оценок с причиной; отчёты по формам 1/112, 2/112, Excel; пробные вызовы.

**Администратор:** состояние всех компонентов, пользователи и группы, журнал аудита, резервные копии и восстановление, настройки.

## 16. Если не работает

| Симптом | Что делать |
|---|---|
| `make up` → «Docker НЕ видит GPU» | п. 8 (Container Toolkit) или `make up-cpu` |
| сборка падает на `curl` моделей | нет доступа к сайтам моделей — п. 14 |
| `База … ОШИБКА` | `docker logs t112-db`; сменили `DB_PASSWORD` после первого запуска — верните прежний или удалите `state/pg` (данные пропадут) |
| Модель: «НЕДОСТУПНА» | вариант А: `curl localhost:1212/v1/models`; вариант Б: `docker logs t112-llm` |
| «не совпадает с served-model-name» | исправьте `LLM_MODEL`, `make restart` |
| распознаёт Vosk вместо GigaAM | `make health` → «Примечание»; `docker logs t112-asr` |
| браузер не открывает страницу | туннель не поднят; на ПК `curl localhost:8080/health` |
| «Нет доступа к микрофону» | входите через туннель на localhost, не через `make open` |
| старший бригады не звонит | бригада не выехала: ей не передан адрес — позвоните и назовите адрес |

Сброс пароля администратора:

```bash
docker exec -it t112 python3 -c "from api import db, auth; db.ex('UPDATE users SET pw_hash=?, active=1 WHERE login=?', (auth.hash_pw('НовыйПароль123'), 'admin')); print('готово')"
```
